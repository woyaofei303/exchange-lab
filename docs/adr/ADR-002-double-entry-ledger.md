# ADR-002: 余额快照与双向账本共同约束资金真值

- 状态：已采纳
- 日期：2026-08-10
- 决策范围：模拟 USDT 入金、可用余额、冻结余额及后续保证金/盈亏入账

## 决策

所有资金变动必须在一个 PostgreSQL 事务中同时完成：写入不可变 `ledger_transactions`、至少两条同资产且 atoms 合计为零的 `ledger_entries`、更新加锁后的 `balances` 快照、写入业务幂等事实和脱敏审计。金额使用 `BIGINT atoms`，USDT scale 固定为 8。

`ledger_entries` 是资金变化的可审计事实；`balances` 是服务低延迟读取及并发控制的物化快照。写入使用 Serializable 隔离和余额行锁，数据库提交是唯一成功边界。相同幂等键与相同参数返回原事务；参数不同则冲突。

## 失败与回滚

- 任一 entry、余额、幂等或审计写入失败，整个事务回滚。
- 对账检查每个事务至少两条 entry 且同一资产净和为零；失败时停止资金写入并调查，不自动“修平”。
- migration down 只用于无生产数据的学习环境；有账本事实时优先应用前向修复并从已验证备份恢复。

## 被拒绝方案

- 只更新余额：无法证明资金来源与去向，也无法可靠重放和审计。
- 使用浮点数：不能提供十进制守恒。
- Redis 作为余额真值：缓存故障或逐出会破坏资金一致性。
- 先写余额再异步补账本：进程崩溃会产生不可恢复的半完成资金变动。
